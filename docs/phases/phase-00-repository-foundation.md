# Phase 0: Repository foundation

## Status

Complete

## Objective

Establish a trustworthy, MIT-licensed open-source starting point for OpenLearn.

## Why this phase matters

Contributors and prospective users need a clear project identity, a visible license, discoverable community expectations, and safe routes for support and security reports before product implementation begins.

## Deliverables

- An MIT license in [`LICENSE`](../../LICENSE).
- A truthful early-stage project overview in [`README.md`](../../README.md).
- Contribution guidance in [`CONTRIBUTING.md`](../../CONTRIBUTING.md).
- Community conduct expectations in [`CODE_OF_CONDUCT.md`](../../CODE_OF_CONDUCT.md).
- Security reporting guidance in [`SECURITY.md`](../../SECURITY.md).
- Support and discussion guidance in [`SUPPORT.md`](../../SUPPORT.md).
- Release-history guidance in [`CHANGELOG.md`](../../CHANGELOG.md).
- GitHub issue templates for bug reports and feature requests.
- A GitHub pull-request template for consistent contribution context.

The repository templates are available through the [bug report form](../../.github/ISSUE_TEMPLATE/bug_report.md), [feature request form](../../.github/ISSUE_TEMPLATE/feature_request.md), and [pull-request template](../../.github/PULL_REQUEST_TEMPLATE.md).

## Workstreams

- **Repository identity:** Keep the project name, purpose, license, and early-stage status consistent.
- **Community health:** Make contribution, conduct, support, and security expectations easy to find.
- **GitHub workflow:** Provide issue intake and pull-request context for future contributions.

## Dependencies

This is the initial project phase. It depends only on the decision to establish OpenLearn as an open-source project and on the initial product direction described in the repository README.

## Risks and decisions

- **Risk:** The repository could imply that planned dashboard or AI behavior is already implemented. **Decision:** Describe those capabilities as planned until their phases meet their exit criteria.
- **Risk:** Contributors may not know where to ask questions or report sensitive issues. **Decision:** Keep support and security routes separate and link them from the repository entry points.
- **Risk:** Community files could drift from the actual project. **Decision:** Treat the repository health files and this phase record as a maintained baseline.

## Exit criteria

- The MIT license and repository foundation files exist.
- The project direction is honestly described as early-stage.
- Contribution, support, conduct, and security routes are discoverable.
- GitHub contribution templates are available.
- The foundation is ready for a bounded product-discovery effort.
